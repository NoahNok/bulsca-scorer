# Packs are rendered to PDF with headless Chrome (Browsershot)

Packs used to be Blade pages that called `window.print()`, so page breaks, margins and background graphics depended on each organiser's browser and print settings, and the "3 heats per page" layout was a hard-coded guess. We now render each Pack's Blade view to a real PDF server-side with `spatie/laravel-pdf` and its Browsershot (headless Chrome) driver, and let the content flow with `break-inside: avoid` instead of fixed chunks. Chrome renders the existing Tailwind 4 layouts (flex, grid, `@page`, repeated table headers) exactly as the browser does. dompdf would have avoided new server dependencies, but it has no flexbox or grid support and would have meant rewriting every template with tables. Gotenberg gives the same fidelity, but it's an extra Docker service to run. The cost of this choice is that the VPS and every dev machine need Node and Chromium installed.
